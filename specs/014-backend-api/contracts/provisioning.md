# Contract — Provisioning

**Base**: `/api/v1/workspaces/{slug}/provisioning` · 출처: 011, 005

ETL 두 유형에만 존재한다. 참조 자산 관리 유형은 이 경로 전체가 `404` 다(011 FR-004).

| Method | Path | 설명 | 요구 롤 | 근거 |
| --- | --- | --- | --- | --- |
| `GET` | `/source-schemas` | 소스 커넥션의 스키마 목록. **메타데이터만** | 파이프라인 저작자 | 011 FR-016·017 |
| `GET` | `/target-schemas` | 유형이 정하는 표준의 버전 목록 | 파이프라인 저작자 | 011 FR-019 |
| `PUT` | `/endpoints` | 소스·목표 스키마 지정 | 플랫폼 운영자 | 011 FR-020·021 |
| `POST` | `/artifacts:author` | AI 저작 요청. 유형별 대상 전체 생성 | 파이프라인 저작자 | 011 FR-022·024 |
| `GET` | `/artifacts` | 대상별 초안 상태 | 파이프라인 저작자 | 011 FR-023 |
| `PATCH` | `/artifacts/{kind}` | 사람 편집. **dry-run 미통과로 되돌림** | 파이프라인 저작자 | 011 FR-036 |
| `POST` | `/dry-run` | dry-run 수행 | 파이프라인 저작자 | 005 FR-026~037 |
| `POST` | `/simulation` | 샘플 시뮬레이션 | 파이프라인 저작자 | 011 FR-026~033 |
| `GET` | `/simulation/{id}` | 결과. 충족도·건수·탈락 사유 **집계만** | 파이프라인 저작자 | 011 FR-026·029 |
| `POST` | `:confirm` | 확정 → 워크스페이스 `operational` | **파이프라인 확정자** | 011 FR-034·040, 013 FR-018 |
| `POST` | `:reject` | 반려 → 저작 단계 복귀 | 파이프라인 확정자 | 011 FR-039 |

## 상태기계 — 거부 규칙

```
schema_selection → authoring → dry_run → simulation → review → confirmed
                                   ↑__________________|  (사람 편집 시 되돌림)
```

| 요청 | 응답 | 근거 |
| --- | --- | --- |
| 스키마 미지정 상태의 `:author` | `409` | 011 FR-020 |
| 저작 대상 중 하나라도 초안 없이 `/dry-run` | `409` + 빠진 종류 제시 | 011 FR-023 |
| dry-run 미통과 상태의 `/simulation` | `409` | 011 FR-025 |
| 시뮬레이션 미통과 상태의 `:confirm` | `409` | 011 FR-032 |
| 자유서식 비식별화에 잔존 식별정보 있는 상태의 `:confirm` | `409` | 011 FR-066 |
| 편집 후 재검증 없이 `:confirm` | `409` | 011 FR-036 |
| 저작자 롤만 가진 사용자의 `:confirm` | `403` | 013 FR-018 |

## 주의

- **SDM ETL은 저작 대상이 4종**(적재·변환·워크플로·**자유서식 비식별화**), OMOP CDM ETL은 3종
- 시뮬레이션은 **실데이터 표본**을 쓴다. 임시 영역은 제한 계층과 동등한 통제를 받고 종료 시
  파기된다. 응답에 원본 값이 실려서는 안 된다 (011 FR-048~053)
- `:confirm` 은 자기 저작분에 대해서도 **허용**된다. 직무 분리 강제는 참조 자산 매핑에만
  적용된다(013 FR-027). 다만 확정 기록에 저작자와 확정자가 각각 남는다(013 FR-028)
