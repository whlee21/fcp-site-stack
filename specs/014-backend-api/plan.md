## Summary

병원 내부망에서 동작하는 단일 컨테이너 Python 서비스로, 워크스페이스·프로비저닝·잡·타깃·롤의
**제어 평면 REST API**를 제공한다. 서비스는 메타데이터와 참조만 다루고 환자 데이터를 통과시키지
않는다. 외부 의존은 Prefect·PostgreSQL·Gitea·Keycloak 넷이며 모두 원내에 있다. UI는 범위 밖이다.

핵심 설계 판단은 **제어 평면 경계를 코드 구조로 강제하는 것**이다. 헌법 원칙 IV가 "대용량
데이터는 제어 평면을 통과해서는 안 된다(MUST NOT)"고 규정하므로, API는 데이터 계층에 연결하지
않고 경로·식별자·상태만 반환한다. 이 제약은 문서가 아니라 **의존 방향과 임포트 린트**로
표현되어야 한다 — 문서로만 두면 지켜지지 않는다.

## Constitution Check

### ⏸ G1 — 데이터 생성 프로젝트: 위반 아님, 스펙 대기

**2026-09-01 재판정.** 초안은 요청의 "프로젝트 관리"를 기능 009의 배제 대상 프로젝트로 읽고
헌법 위반으로 판정했다. **그 판정은 틀렸다.** 요청된 프로젝트는 다른 개념이다.

| | 연구 프로젝트 (009, 범위 밖) | 데이터 생성 프로젝트 (요청된 것) |
| --- | --- | --- |
| 목적 | 연구 목적·요청 단위 작업 묶음 | **물리 스키마를 만드는 정의 단위** |
| 산출물 | 추출물(Extract) | 물리 스키마 |
| 소비자 | **연구자** | 운영 측 |
| 정의 내용 | 멤버십·추출물 수명 | 워크스페이스 공통 스크립트를 불러와 수정 |

헌법 범위 경계는 배제 근거를 *"추출물의 소비자가 연구자이기 때문"* 으로 명시한다. 데이터 생성
프로젝트는 산출물이 물리 스키마이고 소비자가 운영 측이므로 **배제 대상이 아니다**
(헌법 v4.2.2가 이를 명시). 두 개념을 개명해 구분했고, 접두 없는 "프로젝트" 사용은 금지된다.

**그럼에도 이 계획은 데이터 생성 프로젝트 API를 아직 설계하지 않는다.** 헌법 위반이 아니라
**명세가 없기 때문**이다. 이 개념은 기존 스펙의 구조를 바꾼다.

| 스펙 | 무엇이 바뀌는가 |
| --- | --- |
| 011 | FR-022·023·040이 **워크스페이스당 파이프라인 1벌**을 전제한다. 프로젝트마다 공통 스크립트를 파생·수정하면 이 전제가 깨진다 |
| 009 | 타깃이 워크스페이스 직접 소유에서 **프로젝트의 산출물**로 이동한다 |
| 002 | 잡의 필수 귀속이 `target_id` 인데 프로젝트 실행 단위가 되면 재검토가 필요하다 |
| 013 | 연구 프로젝트 스코프 롤을 범위 밖으로 뺐으나, 데이터 생성 프로젝트는 운영 개념이라 롤이 필요할 수 있다 |

plan에서 흡수하면 스펙과 구현이 갈라진다. 이 저장소가 이번 세션 내내 002·003에서 고친 것이
정확히 그 문제다. `TODO(DATA_BUILD_PROJECT_MODEL)`이 확정된 뒤 이 계획에 도메인을 추가한다.

## Technical Context

**Language/Version**: Python 3.13

**Primary Dependencies**: **FastAPI + uvicorn**(ASGI 서버), SQLAlchemy 2.x + Alembic,
`prefect` 클라이언트, `httpx`(Keycloak·Gitea), JWKS 기반 토큰 검증 — 선정 근거는 `research.md`

**Storage**: PostgreSQL 18 — 제어 평면 메타데이터 **전용**

**Testing**: pytest + `pytest-asyncio`. 계약 테스트는 OpenAPI 스키마 대조, 통합 테스트는
외부 의존 4종을 띄운 상태

**Target Platform**: Linux 컨테이너 단일 이미지, 병원 내부망

**Project Type**: web-service (백엔드 단독)

**Performance Goals**: NEEDS CLARIFICATION — 명세의 SC는 사람 조작 시간(분 단위)만 규정하고
API 지연·처리량 목표가 없다. `TODO(PSEUDONYMIZATION_SCALE)` 미해결로 잡 규모도 미정 (R8)

**Constraints**:
- 응답에 환자 데이터·원천 값이 포함되어서는 안 된다 (헌법 II·III)
- 대용량 페이로드가 API를 통과해서는 안 된다 (헌법 IV)
- 런타임 외부 네트워크 호출 없음 (헌법 I)

**Scale/Scope**: 단일 병원. 운영자 소수 + 배정 사용자. 워크스페이스 수십 규모로 **가정**
(명세에 근거 없음 — R8에 가정으로 기록)

```text
src/fcp_api/
├── main.py                  # ASGI 앱 조립, 라우터 등록
├── config.py                # 외부 의존 4종 접속 설정
├── api/                     # HTTP 경계 — 요청/응답 스키마와 라우팅만
│   ├── workspaces.py
│   ├── provisioning.py
│   ├── jobs.py
│   ├── targets.py
│   └── roles.py
├── domain/                  # 순수 도메인 규칙 — 외부 의존 임포트 금지
│   ├── workspace.py         # 유형·계층군·상태 전이 (001, 011)
│   ├── provisioning.py      # 저작→dry-run→시뮬레이션→확정 상태기계 (011)
│   ├── job.py               # 잡 상태·순차 실행·재실행 (002)
│   ├── target.py            # 타깃 레지스트리·동결·보존 (009 범위 안)
│   └── roles.py             # 롤 카탈로그·권한 판정 (013)
├── adapters/                # 외부 의존 — 여기서만 네트워크·DB를 만진다
│   ├── db/                  # PostgreSQL, 제어 평면 스키마 전용
│   ├── prefect.py           # flow 트리거·상태 조회
│   ├── keycloak.py          # 토큰 검증, 사용자·롤 조회
│   └── gitea.py             # 정의 커밋·버전 조회
└── observability/
    └── masking.py           # 정형 식별자 마스킹 — 로거 기본값

tests/
├── contract/                # OpenAPI 스키마 ↔ 구현 대조
├── integration/             # 외부 의존 4종 기동 상태의 흐름 검증
└── unit/                    # domain/ 순수 규칙
```

**Structure Decision**: 단일 프로젝트, **3계층(api / domain / adapters)**. 이 분리는 스타일이
아니라 **헌법 IV를 코드로 강제하는 장치**다.

- `domain/`은 외부 의존을 임포트하지 않는다 → 데이터 계층 커넥션을 가질 수 없다
- `adapters/db/`는 제어 평면 스키마만 접근한다 → 워크스페이스 데이터 계층
  (`{ws}_landing`·`_work`·`_mart`·`_pseudo`)에 커넥션을 만들지 않는다
- 두 규칙을 **임포트 린트로 검사**한다(quickstart 참조)

`frontend/`를 두지 않는다 — UI는 범위 밖이다.
