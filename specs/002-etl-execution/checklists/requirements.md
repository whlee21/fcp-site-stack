### Validation iteration 2 — 2026-08-31

**User Story 4 재실행 방식을 워크스페이스 유형에 따라 분리. 전 항목 통과 유지.**

**이터레이션 1의 결정을 CDM에 한해 뒤집었다**

이터레이션 1의 FR-033은 "중단 지점부터 이어받는 **부분 재개를 수행해서는 안 된다**"였고,
Assumptions는 "단계 단위 부분 재실행은 이번 범위 밖"과 "재개는 부분 재개가 아니라 처음부터
다시 적재하는 것을 뜻한다"로 못 박고 있었다. CDM에 한해 이 금지를 해제했다.

| | 이터레이션 1 | 이터레이션 2 |
|---|---|---|
| SDM 재실행 | 처음부터 깨끗한 재적재 | **처음부터 깨끗한 재적재 (유지)** |
| CDM 재실행 | 처음부터 깨끗한 재적재 | **운영자가 시작 단계 지정, 그 단계부터 재적재** |
| 부분 재개 | 전면 금지 | **CDM에 한해 허용** |

유형에 따라 나눈 이유는 데이터 규모다. SDM은 요청 단위로 확정된 코호트만 다뤄 처음부터
다시 하는 비용이 크지 않고 규칙이 단순한 편이 낫다. CDM은 병원 EHR 전체를 다루므로 앞
단계 반복에만 오랜 시간이 들어 재실행 자체가 실용적이지 않게 된다.

**FR 블록 재편 (FR-033, FR-036 ~ FR-048)**

FR 번호는 이 명세의 관례대로 안정적 ID를 유지했다(기존 번호를 옮기지 않고 뒤에 추가).

- **취소** (FR-026, FR-031, FR-032, FR-034, FR-035): FR-034를 실행 건 단위에서
  **실행 건과 단계 단위** 귀속으로 확장
- **재실행 — SDM** (FR-033, FR-036): 기존 동작을 SDM으로 한정하고, 시작 단계 지정을
  제공하지 않음을 명시
- **재실행 — CDM** (FR-037~FR-048): 시작 단계 지정, 운영자 롤 한정, 지정 가능 범위,
  미지정 시 처음부터, 지정 단계 이후 삭제·이전 재사용, 귀속 이관, 누적 시 최근 것 재사용,
  기록, manifest 단계별 출처, 버전 미확인 시 거부, 재사용 산출물 생성 시각 기록

US4 시나리오 8개 → 20개. Key Entities에 시작 단계 지정 추가. SC 8개 신설.
최종: FR 48개, SC 23개, 수용 시나리오 44개, 엣지 케이스 20개.

**원문에 없지만 도출해서 넣은 것과 근거**

- **FR-043 귀속 이관**: 재사용된 산출물의 귀속을 재개 실행 건으로 옮기지 않으면 원래 실행
  건이 계속 미정리 중단 실행으로 남아 다음 정리에서 **사용 중인 데이터가 삭제된다**. 조용히
  잘못되는 실패라 반드시 필요하다
- **FR-039 지정 가능 범위**: 중단된 실행에서 완료되지 않은 단계를 시작 단계로 지정하면
  존재하지 않는 앞 단계 산출물을 재사용하게 된다
- **FR-046·FR-047 manifest 단계별 출처**: 기능 004는 CDM 스냅샷을 재생성 불가한 원본
  자산으로 다루고(FR-010) manifest 정보가 하나라도 없으면 유효한 자산으로 확정하지 못하게
  한다(FR-012). 중간 재개로 만든 스냅샷은 여러 실행 건의 산출물이 섞이므로, 단계마다 출처
  실행 건과 버전을 기록해야 그 기준을 만족한다. 버전을 확인할 수 없으면 중간 재개를 거부해
  기록되지 않는 조건이 생기지 않게 했다
- **FR-038 운영자 롤 한정**: 원문이 "운영자가"라고 지정했고, 재사용 판단의 책임이 사람에게
  있으므로(FR-048) 권한을 좁히는 것이 맞다

**임의 기본값으로 처리한 것**

  운영자의 판단이며, 시스템은 생성 시각을 기록해 근거만 남긴다(FR-048)
